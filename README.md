# PZ Server UI

Локальное приложение Windows для управления существующими выделенными серверами Project Zomboid. Стек: .NET 10 и .NET MAUI с нативным XAML.

## Что уже реализовано

Можно выбрать папку существующей установки Dedicated Server. Панель проверяет наличие одного из стандартных файлов запуска (`StartServer64.bat`, `StartServer64_nosteam.bat` или `StartServer32.bat`) и запоминает выбор.

Список профилей автоматически читается из `%USERPROFILE%\Zomboid\Server`. Профиль отображается, даже если папка его мира ещё не появилась. В списке можно искать по имени, а в узком окне он открывается кнопкой «Профили». Кнопка «Обновить» повторно читает каталог. Чтобы добавить свою обложку, положи `<имя профиля>.png`, `.jpg` или `.jpeg` в `%LOCALAPPDATA%\PzServerUi\covers` и обнови список; без неё используется нейтральная иконка.

«Обзор» показывает сохранённые лимит игроков, PVP и игровые порты, а не данные работающего сеанса. В «Профиле» находятся пути, основные настройки и песочница. Панель отмечает сохранённые изменения до следующего подтверждённого запуска из приложения и не перезапускает сервер за пользователя. «Моды» показывает отдельно Mod ID и Workshop ID из INI, не проверяя, загрузились ли они. «Консоль» даёт поиск и фильтры по последним строкам живого журнала выбранного сеанса; ввод по умолчанию скрыт.

«Запустить» передаёт имя выбранного профиля штатному лаунчеру Dedicated Server. Поддерживается однострочная команда запуска `zombie.network.GameServer` с передачей `%1 %2` или `%*`. Если параметры не передаются или профиль жёстко задан в скрипте, запуск отменяется. Панель не запускает игровой клиент. «Остановить» после подтверждения отправляет штатный `quit` только работающему сеансу, запущенному из панели. Обнаруженные внешние процессы не считаются готовыми и не управляются панелью.

Панель показывает «Работает» после строки `*** SERVER STARTED ****` в сетевом логе того сеанса, который она запустила. До сигнала она показывает ожидание, а если лаунчер завершился раньше, сообщает об ошибке. Для каждого запуска создаётся отдельный временный журнал в `%LOCALAPPDATA%\PzServerUi\sessions`; общий лог игры не используется. Это не проверка доступности порта извне и не распространяется на ранее или вручную запущенные серверы.

## Сборка и проверка

Для сборки на Windows нужны .NET 10 SDK и workload `maui-windows`. Установить workload на машине разработки:

```powershell
dotnet workload install maui-windows
```

Собрать и запустить приложение:

```powershell
dotnet build
dotnet run --project src/PzServerUi
```

Проверить сценарии выбора установки можно без MAUI и установки игры:

```powershell
dotnet run --project tests/PzServerUi.Application.Tests
```

## Windows-релизы и номера версий

- **Проверочные сборки.** GitHub Actions запускает тесты и собирает Windows x64 ZIP на PR в `main` и при обновлении `main`. ZIP лежит в артефакте `windows-release` соответствующего запуска. Такие сборки помечены `v0.0.0-ci.<номер запуска>.<попытка>`, обычная локальная сборка показывает `v0.0.0-dev`.
- **Стабильный релиз.** После проверки `main` создай и отправь тег `vX.Y.Z` на нужном коммите `main`. Workflow соберёт этот коммит и прикрепит `PzServerUi-vX.Y.Z-win-x64.zip` к GitHub Release. Повторно использовать существующий релизный тег не нужно: для новой версии создай новый тег.
- **Запуск.** Распакуй весь ZIP в одну папку и запусти `PzServerUi.exe`. Архив содержит библиотеки .NET и Windows App SDK. Версия видна в заголовке окна, а `version.json` в архиве содержит версию и точный коммит. Автоматического обновления в приложении нет.

Пример выпуска после слияния нужных изменений:

```powershell
git fetch origin main
git tag -a v0.1.0 origin/main -m "PZ Server UI v0.1.0"
git push origin v0.1.0
```

Локальная проверка той же упаковки без Git-тега и публикации:

```powershell
.\scripts\New-WindowsRelease.ps1 -BuildVersion 0.0.0-ci.1.1 -OutputDirectory "$env:TEMP\PzServerUi-build"
```
